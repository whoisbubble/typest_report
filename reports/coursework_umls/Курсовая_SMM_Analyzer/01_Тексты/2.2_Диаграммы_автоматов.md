# 2.2. Диаграммы автоматов

SM_01_Кампания описывает Campaign.status: DRAFT → ACTIVE ↔ PAUSED → COMPLETED → ARCHIVED; допускаются ACTIVE → COMPLETED и архивирование неактивного черновика. Из COMPLETED возврата нет: новый этап работы оформляется новой кампанией. Пауза запрещает новые публикации, импорт и денежные операции, но допускает анализ уже собранных данных и отчётность. Архив доступен только для чтения.

SM_02_Импорт описывает ImportJob.status: QUEUED → VALIDATING → APPLYING → SUCCEEDED. Ошибка проверки/исчерпание повторов ведёт к FAILED. Истечение аренды незавершённого задания возвращает его в QUEUED при attempts < 3. attempts увеличивается при захвате. APPLYING и переход в SUCCEEDED коммитятся атомарно с предметными данными; поэтому сбой после коммита не создаёт повторного применения.

SM_03_Отчёт описывает Report.status: DRAFT → PUBLISHED. Публикация фиксирует содержимое и publishedAt; изменение запрещено. Исправление создаёт новый DRAFT с previousReportId, а старый опубликованный отчёт остаётся доступным как предыдущая версия.

Начальные псевдосостояния показывают создание объекта, а не вход пользователя. Конечные псевдосостояния обозначают окончание жизненного цикла процесса; архивирование не удаляет строку из БД.
