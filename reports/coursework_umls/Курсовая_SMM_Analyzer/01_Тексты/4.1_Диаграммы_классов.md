# 4.1. Диаграммы классов проектирования

DES_01_Сущности — постоянные сущности, ключевые атрибуты, операции и кратности.
DES_02_Сервисы — контроллеры, прикладные сервисы, интерфейсы репозиториев и анализа, реализации TypeORM и RuleBasedAnalyzer. Зависимость от интерфейса отражает инверсию зависимостей; реализация интерфейса — пунктирная линия с пустым треугольником.

## Ограничения хранилища
Все сущности имеют UUID id; бизнес-записи имеют agencyId, createdAt, updatedAt. Изменяемые записи имеют version для оптимистической блокировки. Ссылки внутри агентства проверяются составными внешними ключами (agencyId, foreignId) на уникальные (agencyId,id).

User.email уникален после нормализации; CampaignMember уникален по (campaignId,userId), ClientUser — по (clientId,userId). Допустимая роль назначаемого сотрудника проверяется сервисом в транзакции; клиентская роль не может быть CampaignMember.
Publication уникальна по (agencyId,platform,externalId). MetricSnapshot — по (publicationId,capturedAt). Comment — по (publicationId,externalId).
ImportJob — по (publicationId,fileSha256). AnalysisJob — по (publicationId,inputRevision,providerVersion). AnalysisResult — по (jobId,commentExternalId).
FinancialEntry.amount > 0; currency='RUB'; direction ∈ {INCOME,EXPENSE}, status ∈ {POSTED,REVERSED}. replacesId уникален при ненулевом значении; связь исправления относится к той же кампании. idempotencyKey уникален в рамках agencyId.
Campaign.startDate ≤ endDate, budget ≥ 0. Report.periodStart ≤ periodEnd; previousReportId относится к той же кампании.

Удаление клиента, пользователя и кампании с зависимостями запрещено; используется деактивация или архив. AuditEvent добавляется транзакционно, обычная роль приложения не имеет UPDATE/DELETE на таблицу аудита. Session хранит хеш случайного токена, userId, expiresAt и revokedAt.

Схема классов показывает существенные поля, а не полный DDL. Скрытые на схеме общие поля и составные ключи определены здесь; это спецификация будущей реализации.
