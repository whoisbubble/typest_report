# 4. Модель проектирования

Архитектура — модульный монолит NestJS и отдельный процесс Worker из той же серверной кодовой базы; Next.js отвечает за интерфейс. Модули: Identity, Campaigns, Publications, Imports, Analysis, Finance, Reports, Audit.

Контроллеры принимают DTO, проверяют формат и вызывают сервисы. AccessPolicy объединяет роль, agencyId, CampaignMember и ClientUser. Сервисы обеспечивают правила и транзакции; интерфейсы репозиториев скрывают TypeORM. Анализ зависит от AnalysisProvider, что позволяет позже подключить ML без изменения пользовательских сценариев. Методы сущностей изменяют состояния через разрешённые переходы; свободная запись status из DTO запрещена.

Один код ошибок: 401 — нет действующей сессии; 403/404 — нет доступа; 409 — конфликт версии/идемпотентности; 422 — неверные предметные данные. Сервер не возвращает внутренние детали БД.

## Контракт импорта
Файл UTF-8 JSON, schemaVersion=1, publicationExternalId совпадает с выбранной карточкой, capturedAt содержит часовой пояс. metrics содержит views, likes, commentsCount, shares — неотрицательные целые; comments — массив externalId, text, postedAt, authorExternalId (может отсутствовать). Поле text ограничено 10 000 символами. Максимум 10 000 комментариев и 20 МБ на файл. Поля площадки не трактуются как проверенные персональные данные.

Пример структуры:
```json
{"schemaVersion":1,"publicationExternalId":"video-001","capturedAt":"2026-10-19T10:00:00Z","metrics":{"views":1000,"likes":50,"commentsCount":12,"shares":5},"comments":[{"externalId":"c-001","text":"Полезный разбор","postedAt":"2026-10-19T09:00:00Z","authorExternalId":"author-01"}]}
```

Частичная выгрузка комментариев допустима: отсутствие комментария в файле не удаляет ранее сохранённый. При изменении текста совпавшего externalId обновляется Comment и увеличивается commentsRevision публикации. Снимок с той же capturedAt и теми же метриками считается повтором; с другими значениями — конфликт 409, без скрытой перезаписи истории.

## Идемпотентность и фоновые задания
ImportJob уникален по (publicationId, fileSha256). QUEUED выбирается транзакционно с FOR UPDATE SKIP LOCKED; worker выставляет leaseUntil и attempts. После истечения аренды job повторяется не более трёх попыток. Изменение предметных данных, запись аудита и SUCCEEDED выполняются в одной транзакции. Файл хранится в закрытом томе, имя формируется сервером, исходное имя не используется как путь.

AnalysisJob уникален по (publicationId, inputRevision, providerVersion). В транзакции фиксируются комментарии в inputSnapshot и версия набора. Provider получает этот снимок и возвращает ровно один результат на входной комментарий. Сбой провайдера оставляет задание FAILED без частичного набора результатов; повторяется само задание по общей политике аренды. Повторный импорт может сделать результат устаревшим, но не меняет его историю.

## Черновики и отчёты
Report хранит internalPayload, clientPayload, sourceRefs, periodStart, periodEnd и version. sourceRefs содержит ID снимков и заданий анализа. Черновик получает согласованный снимок чтения. Публикация повторно проверяет доступ, status, version и актуальность включённого анализа, фиксируя clientPayload. Заказчику API никогда не сериализует internalPayload. Новая информация после публикации не меняет опубликованный документ.
