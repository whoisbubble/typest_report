# 5. Модель реализации

Здесь «реализация» означает проект состава программных артефактов и размещения. Готовое веб-приложение и обученная модель в этот комплект не входят.

Предполагаемая структура: apps/web (Next.js), apps/api (NestJS), apps/worker (NestJS application context), packages/contracts (DTO и схема импорта), packages/domain (сущности и интерфейсы), packages/persistence (TypeORM, миграции), infra (Docker Compose, конфигурация reverse proxy).

Worker использует те же сервисы импорта и анализа, но не открывает публичный HTTP-порт. В браузер не поставляются секреты, код доступа к БД и правила серверной авторизации. Next.js обращается к API по общему внешнему origin; для публичных страниц и статики используется Web, для /api — NestJS.

Базовые программные артефакты: web image, api image, worker image, миграции БД, reverse-proxy config. Версии зависимостей следует зафиксировать при начале разработки; данный комплект не утверждает, что проект собран или развёрнут.
