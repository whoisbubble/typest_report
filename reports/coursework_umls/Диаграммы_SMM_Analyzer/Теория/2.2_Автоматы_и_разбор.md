# 2.2. Автоматы: состояния, события и восстановление результата

Редакция после аудита. Основа: [Анисимов, §§12.6–12.8](https://sites.google.com/site/anisimovkhv/learning/pris/lecture/tema12/tema12_3).

## Обозначения

Скруглённый прямоугольник — состояние, в котором интерфейс может находиться некоторое время. Чёрная точка — начало, точка в окружности — завершение. Стрелка — допустимый переход. Подпись читается как `событие [условие] / действие`. `entry` выполняется при входе; `do` обозначает деятельность в состоянии. Внутренняя реакция остаётся в состоянии и не повторяет entry. Два соединённых кружка у состояния означают скрытую детализацию в отдельном автомате. Переход без события является переходом по завершении; условия завершённой проверки взаимоисключающие.

## 05. Контекст интерфейса

![Контекст](../PNG/05_SM_context.png)

Граница — рабочая область после аутентификации. Большая рамка является составным состоянием. Меню открывает один раздел при наличии полномочия; отсутствие права обрабатывается внутренней реакцией меню. Раздел данных объединяет кампании, финансы и доступ. Просмотр объединяет аналитику и кабинет заказчика в пределах прав конкретной роли.

Импорт запускает SM_02, отчёты — SM_03. Их завершение возвращает управление в меню. Из других разделов возврат вызывается закрытием. Выход завершает сеанс только при отсутствии незавершённой операции и после решения судьбы несохранённых правок. Неизвестный итог записи тоже считается незавершённой операцией. Закрытие вкладки не отменяет уже выполненную серверную транзакцию.

## 06. Импорт

![Импорт](../PNG/06_SM_import.png)

Форма → проверка → выполнение → показ результата — основной путь. Подтверждённый отказ ведёт к ошибкам, исправление возвращает к вводу. Для новой исправленной команды создаётся новый ключ. Для повторной отправки **той же незавершённой команды** ключ остаётся прежним.

Потеря связи переводит в «Уточняется итог запроса». Клиент вызывает getImportStatus(key). Если сохранённый итог найден, показывается результат или подтверждённый отказ. `notFound` не доказывает откат: запрос мог ещё выполняться. Разрешён безопасный повтор исходной команды с прежним ключом, но не создание новой команды с новым ключом. Если файл недоступен после перезагрузки браузера, пользователь повторно выбирает тот же файл, его хеш проверяется перед повтором.

Метаданные PendingImport сохраняют ключ, публикацию и хеш; File хранится только в памяти. Сам метод recover использует сохранённое состояние. Повторы выполняются с задержкой и не запускаются конкурентным бесконечным циклом. При недоступности сети состояние неопределённости сохраняется честно; получение окончательного результата зависит от восстановления связи.

## 07. Отчёт

![Отчёт](../PNG/07_SM_reports.png)

В редакторе можно сохранить выводы через saveDraft и пересчитать содержимое через refreshDraft с ожидаемой revision. При конфликте сервер не перезаписывает чужие правки; форма показывает замечание и предлагает перечитать рабочую версию. Внутренние реакции не означают безусловного успеха: ошибка отображается в том же редакторе.

Публикация проходит проверку и атомарную фиксацию. Потеря ответа ведёт в уточнение итога через getPublicationStatus(key). PendingPublication хранит исходные reportId, expectedRevision и key; повтор не берёт более новую revision из случайно открытого экрана. Сервер сопоставляет ключ с конкретным пользователем, отчётом и revision. Отказ и успешная фиксация — разные события; неизвестный результат не считается отказом.

Из опубликованного результата открывается новая рабочая revision **того же reportId**. Старый снимок в report_versions не изменяется. Закрытие доступно из ввода, подтверждённых ошибок и результата. Пока исход неизвестен, штатное закрытие процесса не выдаётся за отмену записи.

Все состояния достижимы из начала и имеют потенциальный путь к завершению. Состояние ожидания не обещает гарантированного ответа при постоянно отключённой сети. Серверная проверка прав остаётся обязательной независимо от состояния кнопок.
