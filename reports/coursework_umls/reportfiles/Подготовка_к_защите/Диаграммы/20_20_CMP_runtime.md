**Перед разбором:** соответствующая глава [общего учебника](../Учебник_UML_и_разбор_21_диаграммы.md). **Задача рисунка:** показать части работающей системы и зависимости от предоставляемых интерфейсов без привязки к компьютерам.

![Состав исполняемых компонентов системы](../../images/20_CMP_runtime.png)

## Где какие элементы и что они означают

Клиентский JS, Nginx, Next.js, API, worker, PostgreSQL, копирование и архив — отдельные компоненты. В секциях подписано «предоставляет» и «требует». На стрелках указаны HTTPS, Web/HTTP, REST/JSON, SQL и SFTP. Все штриховые стрелки здесь — зависимости, а не маршрут алгоритма.

## Как читать нашу схему

Браузер получает страницы/JS через Nginx. Proxy направляет Web-запросы в Next.js, /api/* — в NestJS. API определяет личность и вызывает сценарии, которым нужна БД. Worker независимо читает сохранённый вход публикаций и пишет анализ. Среда резервирования читает PostgreSQL и передаёт зашифрованную копию в архив. Ответы идут в рамках того же интерфейса без второй стрелки зависимости.

## Зачем именно такое решение

Общий SQL-интерфейс позволяет API и одному worker обмениваться состоянием без отдельного брокера на первом этапе. ImportService выполняется API; worker не является скрытой очередью импорта. Отчёты остаются в reports/report_versions PostgreSQL, а архив служит восстановлению БД, не выдаче опубликованного отчёта заказчику.

## Что ещё знать по теории

Предоставляемый интерфейс можно изображать кружком, требуемый — сокетом. Текстовый вариант должен сохранять однозначность контракта; нельзя считать любой соединительный штрих вызовом метода.

## Вопросы для защиты с ответами

- **Почему backup зависит от БД, если данные идут из БД?** Зависимость означает использование её интерфейса, а не направление всех данных.
- **Здесь один компонент — один компьютер?** Нет, на одном сервере могут работать несколько процессов; размещение отдельно на 21.
- **Где интерфейс-кружок?** Выбрано текстовое представление provided/required в секциях.
- **Worker учит ML?** Нет, предусмотрена заменяемая аналитическая реализация для будущего этапа.
